# Профессии и воркфлоу

Профессия содержит набор воркфлоу. Стартовый воркфлоу называется «Дефолтный»;
остальные можно создавать и редактировать независимо. Название профессии
показывается в общем переключателе, а название воркфлоу — в его редакторе.
В форме профессии нет выбора «дефолтного воркфлоу».

Страница `/workflows` и её обновление после сохранения используют коллекцию
выбранной профессии. Создание воркфлоу через эту страницу добавляет его в ту же
коллекцию. Чужой воркфлоу в сохранённом URL перенаправляет на коллекцию выбранной
профессии; неизвестный ID остаётся ошибкой. Проверка принадлежности действует
и для изменения воркфлоу и фаз через API с явным контекстом профессии.

Связь коллекции хранится в `profession_workflows`. Миграция переносит прежние
связи, сохраняя ID, фазы, инструкции, задачи и историю. Старые общие шаблоны
остаются общими; новые UI-воркфлоу создаются внутри одной профессии.
Откат миграции разрешён только пока коллекции можно восстановить из прежних
связей; дополнительные связи требуют восстановления из резервной копии.

Технические маршруты `/namespaces`, `/api/namespaces`, параметр `namespace_id`,
CLI-команды и идентификаторы сохранены для совместимости. В пользовательском
интерфейсе сущность называется «Профессия» (`Profession`, `Professions`).

`projects.workflow_id` пока сохраняется для прежнего контракта задач и Fleet.
Он не определяет список доступных воркфлоу и не редактируется в форме профессии.
Перенос исполнения задач на произвольный воркфлоу коллекции — отдельная
миграция контракта. Hermes и его upstream-код эта правка не изменяет.
