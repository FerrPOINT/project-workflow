# Профессии и воркфлоу

Профессия содержит набор воркфлоу. Стартовый воркфлоу называется «Дефолтный»;
остальные можно создавать и редактировать независимо. Название профессии
показывается в общем переключателе, а название воркфлоу — в его редакторе.
В форме профессии нет выбора «дефолтного воркфлоу».

Страница `/workflows` и её обновление после сохранения используют коллекцию
выбранной профессии. Создание воркфлоу через эту страницу добавляет его в ту же
коллекцию. Чужой воркфлоу в сохранённом URL перенаправляет на коллекцию выбранной
профессии; неизвестный ID остаётся ошибкой. Проверка принадлежности действует
и для изменения воркфлоу и фаз через API с явным контекстом профессии.

Связь коллекции хранится в `profession_workflows`. Миграция переносит прежние
связи, сохраняя ID, фазы, инструкции, задачи и историю. Старые общие шаблоны
остаются общими; новые UI-воркфлоу создаются внутри одной профессии.
Откат миграции разрешён только пока коллекции можно восстановить из прежних
связей; дополнительные связи требуют восстановления из резервной копии.

Текущие стартовые каталоги (legacy v2 и Base v4) создают семь профессий с
русскими названиями и описаниями. Технические namespace/profile/CLI keys
сохраняют закреплённые значения и не выводятся из отображаемого названия.
Повторная инициализация локализует только нетронутые прежние имена и описания;
авторские подписи сохраняются. Исторические recipes v1/v3 и их wire symbols
остаются закреплёнными; при наблюдении v3 допускается соответствующая роли
русская подпись без изменения технической привязки.

Штатная managed-инициализация не создаёт универсальную профессию «Основной».
Явный compatibility helper для пустого unmanaged editor не добавляет её,
если в установке уже есть профессии. Существующие записи с данными не удаляются
инициализацией: ненужная пустая запись удаляется отдельно через owner API,
который запрещает удаление профессии с задачами и сохраняет её процессы.

Технические маршруты `/namespaces`, `/api/namespaces`, параметр `namespace_id`,
CLI-команды и идентификаторы сохранены для совместимости. В пользовательском
интерфейсе сущность называется «Профессия» (`Profession`, `Professions`).

`projects.workflow_id` пока сохраняется для прежнего контракта задач и Fleet.
Он не определяет список доступных воркфлоу и не редактируется в форме профессии.
Перенос исполнения задач на произвольный воркфлоу коллекции — отдельная
миграция контракта. Hermes и его upstream-код эта правка не изменяет.


Профессия не задаёт общий профиль запуска. Форма редактирует название,
CLI-команду, описание, иконку и цвет; поля «Ключ запуска» и «Профиль запуска
агента» удалены вместе с чтением и записью этого параметра из формы.
Принятая модель: если профиль необходим, он относится к конкретному workflow
в рамках профессии. Новый редактор и маршрутизация таких профилей пока не реализованы.

Прежнее `projects.launch_profile` сохраняется только как legacy-контракт API,
установленных каталогов и admission. Обычное редактирование профессии не
отправляет этот ключ и не обнуляет прежнюю привязку. Удаление legacy-поля и
перенос исполнения требуют согласованной миграции; скрытие поля её не заменяет.
Отдельного реестра агентов, назначения агента фазе, `projects.role_key` и
`execution_description` нет. Существующий `code` идентифицирует профессию.

Для одного Tracker task подготовлен отдельный opt-in
[preset single-task-v1](single-task-professions.md): семь профессий, восемь режимов,
24 фазы. Architect использует существующий `decomposition` как архитектуру/план
внутри задачи; children и integration barriers не создаются. Preset содержит
готовые инструкции; [opt-in установка](single-task-installation.md) добавляет
собственное семейство через existing bootstrap/readback. Live assignment/routing
остаётся pending parent и не переключает legacy execution.

Инициализация варианта `base` создаёт семь профессий с разными иконками и цветами
и полные стартовые воркфлоу по закреплённому Base v4: 11 режимов, 33 фазы и
116 инструкций. Цвет профессии применяется к её обозначению и переключателю;
кнопки и логотип приложения сохраняют общие стили. Списки коллекций видны
при любом положительном количестве записей.

Обновление распознаёт обе опубликованные редакции Base v3 по полному набору
сохранённых фаз, инструкций, проверок и evidence. Первоначальная редакция из
`674aab3` сохранена в `base_sdlc_catalog_v1_frozen.json` с точным SHA-256;
неизвестные изменения прежнего каталога останавливают обновление. Новая v4
добавляется отдельными mode/phase ID, а исторический admission выбирает рецепт
по своему закреплённому catalog SHA-256.

Обновление сохраняет допустимый выбор редактора `sync`/`parallel` у прежних
инструкций. Проверка admission исполняемой конфигурации остаётся строгой;
правило сохранения авторских настроек применяется только при переносе каталога.

Сайдбар сохраняет установленную навигацию «Процессы» и «Выполнения задач».
Фазы открываются из выбранного процесса; переключение воркфлоу или профессии
сбрасывает чужой режим. Общий контекст `project_scope=all` сохраняется также
при переходах в другие сервисы. Страница команд CLI сохраняется.
