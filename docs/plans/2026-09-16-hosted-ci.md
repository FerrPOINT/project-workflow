# Hosted CI Implementation Plan

**Status:** completed — historical implementation record.

**Goal:** Make `project-workflow` continuously verifiable on its `master` branch with the existing local quality and runtime gates.

**Architecture:** GitHub Actions runs the existing pinned `uv` commands in one job, backed by an isolated PostgreSQL 16 service for integration coverage. A separate job validates the repository Compose stack, waits for the native health check, and always cleans up containers and volumes.

**Tech Stack:** GitHub Actions, `astral-sh/setup-uv`, Python 3.11 dependencies pinned in `constraints.txt`, PostgreSQL 16, Docker Compose.

---

## Task 1: Define the quality workflow contract

**Files:**
- Create: `.github/workflows/ci.yml`
- Test: `tests/test_docs_quality.py`

**Steps:**
1. Add a regression test that requires a `master`-triggered workflow with unit/UI tests, PostgreSQL integration tests, coverage, ruff, mypy and Compose readiness.
2. Run the test and confirm it fails while no workflow exists.
3. Add the workflow using the pinned `uv` invocation from `docs/quality-gate.md` and a PostgreSQL service matching the integration-test contract.
4. Re-run the focused test and validate workflow structure through repository checks.

## Task 3: Prove the gates locally

**Files:**
- Test: `.github/workflows/ci.yml`
- Test: `tests/`

**Steps:**
1. Run the focused documentation/workflow regression test.
2. Run the full non-integration suite, ruff and mypy from the existing `.venv`.
3. Run real PostgreSQL integration tests against an isolated local PostgreSQL using environment variables and without printing credentials.
4. Validate `docker compose config -q` and `/health` for standalone Compose.
5. Review the diff, commit the coherent CI increment and publish it through a pull request.
