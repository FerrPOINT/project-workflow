# Подключение общей дизайн-системы

Продукт использует @pdlc/ui 0.3 и опубликованный документ Admin. Общие controls,
цвета, шрифты, плотность, скругления и popup принадлежат Base; запросы,
права, данные и callbacks сохраняются здесь. UI/SDK/skills pins независимы.

Канонический контракт: services-base/docs/platform/DESIGN_SYSTEM.md.
Компоненты искать через pdlc-ui search → show → example. Не создавайте
копии примитивов, собственный Toaster и глобальные определения Base tokens.
Существующие source-компоненты и preview получают общий UI; исторические
прототипы не являются установленным приложением. Установка выполняется отдельно.

PLATFORM_BRANDING_URL — явный public browser endpoint опубликованного branding.
Пустое значение сохраняет defaults. CSS/JS/fonts в templates/base экспортируются
штатным export-ssr.mjs; не редактируйте подготовленные файлы вручную.

Выбор иконки профессии — Base select_control + choice-runtime. Workflow передаёт
каталог SVG и renderOption; собственных popup, Escape и возврата focus нет.
Программная смена value завершается refreshChoice без input/change и записи.

Принятый UI pin: `4856b4ffc40bc1b47066e5e8410ba4a7217b2201` в `.base-ui-revision`.
Текущий перенос SSR проверяется на собственном Base source-кандидате; экспорт
его ресурсов ещё не является принятием нового UI pin или обновлением runtime.
SDK и skills pins независимы; установка этим source-кандидатом не выполняется.

## SSR-композиции собственного source-кандидата

Страница ошибки использует page_header, badge, state и отдельную native
button-ссылку возврата. HTTP status, сообщение и back URL принадлежат Workflow;
возврат не выдаётся за повтор запроса. Общие focus, ссылки, scrollbar и оформление
account принадлежат Base. Ограничение видимости до проверки доступа сохраняется.

Детали задачи используют page_header с одним адаптивным действием «Задачи»,
metric, progress, badge, card/card_content, notice, section_header,
section_navigation и native disclosure. Номер фазы сопровождается доступным
текстом «Фаза»; хронология, группы, выбранная профессия, исходные счётчики,
даты и контракты не заменяются общей библиотекой. Схема timeline и расположение
разделов остаются предметной композицией Workflow.

Соответствие вердиктов tone задаётся в шаблоне владельца: pass → success,
partial/rollback → warning, blocked → danger, delegate → info; неизвестный
вердикт сохраняет исходную подпись и получает neutral. Исторические результаты
не объявляются новыми live alerts. Их списки и сообщения сохраняют autoescape.

Для подготовленного текста используется SSR prose из Base. Macro не выполняет
Markdown/HTML из строк и не отменяет escaping. Отчёт исполнителя сохраняет
пробелы и переносы через white-space:pre-wrap; это свойство содержимого, а не
продуктовая копия шрифта, размеров или цветов. При нулевом объёме progress
остаётся неопределённым для assistive technology; исходное 0 / 0 не переписывается.

Локальные unit/router проверки выполняются с изолированной временной SQLite;
IAB проверяет публичные Base macros на синтетической композиции без маршрутов
Workflow, SSO, credentials и записей. Это не authenticated-приёмка установленного
Workflow. Общий check-ui-contract пока требует отсутствующий docs/ui-routes.json;
полноценный route manifest и интеграционный gate остаются открытыми. Пустой
фиктивный manifest не заменяет их проверку.

Список задач использует общую Table и linked Card. В мобильном представлении
ссылка охватывает всю карточку; namespace URL и исходные data-task-key/status/
verdict сохраняются. DescriptionItem выводит пары dt/dd внутри продуктового dl;
Base владеет их шрифтом и переносом, Workflow — составом полей и сеткой. Пустая
выдача использует state в обеих responsive-композициях. Декоративная SVG-иконка
профессии сохраняет path/цвет из модели внутри общего Badge; радиус, фон, размер
метки и размер иконки не оформляются отдельным namespace-pill.

Standalone sso_entry использует platform_login и общие React/SSR стили Base.
Его ранний выбор темы, callback bridge, login-required/error, native URL входа и
отсутствие действия при 403 сохраняются. Macro не выполняет SSO и не загружает
продуктовые данные. Подключение опубликованного branding к отдельному entry
этим переносом не расширялось: общие tokens и тема не доказывают runtime-публикацию.
Реальные credentials и установленный runtime не используются для source-проверки.
В head standalone-страницы задан viewport width=device-width/initial-scale=1,
чтобы мобильные размеры контролов применялись к настоящей ширине устройства.
Масштабирование пользователем не запрещено.

Редактор workflow использует segmented RadioGroup для выбора «Список / Схема»,
SectionHeader для названия workflow и фаз, Badge для счётчиков, Prose для
пояснения удаления и ResourceState для пустых каталогов. Статическая навигация
и её обновление после запроса используют одну owner-композицию с inert template;
имена и счётчики подставляются через textContent. Продукт сохраняет native button,
workflow ID, pending-блокировку, маршруты и правила изменения фаз.

Переключение вида, переход к фазе и выбор режима больше не дублируются между
администратором и читателем. Оба получают одинаковые классы Card/ResourceListRow;
восстановление phase-view-mode не записывает настройку, invalid игнорируется,
недоступный storage не мешает работе. Запись предпочтения выполняется только
после изменения выбранного radio; программная синхронизация не создаёт change.
Это продуктовый адаптер представления, а не новый общий механизм сохранения.

Source-проверки разделены: owner JS выполняется на отрендеренных role-вариантах
в Node и проверяется на синтаксис; маршруты используют изолированную SQLite.
IAB проверяет публичную композицию SectionHeader/RadioGroup/Card/Badge/State
Base, без запуска Workflow, SSO или запросов к продуктам. Наличие такой композиции
не закрывает authenticated-приёмку редактора установленного приложения.

Редактор фазы также использует общие PageHeader, SectionHeader, DescriptionItem,
Badge, Prose и ResourceState. В read-only режиме название фазы — h2 внутри
PageHeader, оформленный общим page-title; единственный h1 остаётся у страницы.
Редактируемое название использует heading-вариант Input. Цвета и размеры
больше не задаются отдельными wiki-header/wiki-section/check-list/evidence-list
правилами. Интервалы секций задаются общим base-page-stack.

Проверки и подтверждения сохраняют native ul/li и исходные data-id. Публичные
классы ResourceList на ul и macro resource_list_row внутри li соответствуют
каноническому SSR-контракту Base. Flex-раскладка текста, декоративной пиктограммы
и действия остаётся продуктовой композицией; пиктограмма не выдумывает результат
проверки. Read-only текст использует Prose, editable поле — Textarea/autosize Base.

Сохранённые и новые строки рендерит один owner macro phase_text_item. Для новых
строк используется inert template; добавление только создаёт поле, инициализирует
autosize и переводит focus. Запись начинается при существующем событии редактирования.
Неудачное удаление возвращает тот же DOM-элемент и счётчик. Пустые состояния и
метка параллельной группы тоже клонируются из общих macros, без второй HTML-копии.
Payload, очередь, dirty tracking, readback и обработчики API сохранены.

Боковая навигация и scroll offsets используют shell-header-height Base вместо
собственной фиксированной высоты шапки. Оставшийся CSS описывает расположение
предметных секций и действий, а не отдельную тему контролов. Source gate и
публичная композиция Base не подменяют authenticated-проверку Workflow.


## Один заголовок редактора инструкций

Страница инструкций использует общий page_header с единственным полным названием
фазы и одной native button-ссылкой возврата. Переносы текста и расположение действий
при узком экране принадлежат Base; отдельные мобильные заголовок и кнопка удалены.
URL возвращения сохраняет profession_id выбранного namespace. Номер шага использует
badge appearance=counter, пустой список — state(empty). Продуктовые data-атрибуты,
семь handlers и весь extra_script сохранены без изменений.

Удалены неиспользуемые локальные styles dot/status/row/btn-group после сверки
markup, macro arguments и selector references. row-actions и сетка инструкций
сохранены как предметная компоновка. Scoped unit/router проверки — 38 PASS и
6 subtests; shell — 38 PASS и 28 subtests, после удаления CSS адресный повтор
трёх затронутых контрактов — PASS. Ruff изменённых тестов — PASS.

IAB проверяет публичную синтетическую SSR-композицию Base: три темы, standard/large,
320/1920 px, один link, отсутствие overflow и минимум 44 px на мобильном. Шрифт
берётся из рассчитанных tokens, крупный режим меняет текст 14 → 16 px. Это не
браузерная приёмка установленной страницы Workflow и не проверка authenticated UI.


## Заголовки и масштаб типографики

Список задач и редактор фазы используют одну полную подпись h1 внутри PageHeader
на любой ширине. Из task_detail удалены неиспользуемый header_title и CSS мобильной
подмены; видимый PageHeader с исходным task_key и единственной ссылкой возврата
сохранён. В трёх шаблонах scripts и handlers не менялись. Scoped проверки —
4 PASS и 3 subtests; итоговый shell gate — 39 PASS и 31 subtest. Ruff PASS.

В base/dashboard/instructions/namespaces/workflows 11 фиксированных размеров
текста заменены на --base-font-body/label, line-height — на --base-line-body,
моноширинный текст — на --base-font-mono. Удалён мёртвый .page-header h1: текущий
контракт использует .base-page-header. Предметная стрелка timeline сохраняет
18 px как размер декоративного символа; DOM-селектор и управление порядком шагов
сохранены. Остальные CSS-declarations и extra_script этих шаблонов не менялись.

Публичные SSR-композиции Base проверены в IAB: три заголовка, три темы, два
масштаба и 320/1920 px — 36 сочетаний. Один h1, один native link, полный длинный
ключ и отсутствие overflow; typography 14/12/24 → 16/14/28 px. Enter следует href.
Проверка выполнена без рендеринга продуктовых страниц и без runtime/credentials;
она не заменяет authenticated-приёмку Workflow.

## Пустой каталог и выбор цвета профессии

Readonly пустой каталог использует Base state с текстом «Пока ничего не создано.»;
при существующем каталоге без выбора — «Выберите профессию для просмотра.».
Недостижимые заглушки внутри скрытого namespace-nav удалены. Для администратора
сохраняется существующая форма первого создания и фокус на названии.

namespaceThemeColor использует native color Input с общими классами Base вместо
theme-color-input. id/name/value, oninput, FormData, JSON payload и программное
обновление цвета не менялись. Собственная иконка и предметная цветовая identity
профессии остаются отдельной задачей; ProjectAvatar её автоматически не заменяет.

Соседний мобильный переключатель разделов сохраняет доступное имя, его label скрыт.
Scoped tests: 6 PASS, 2 subtests; Ruff, format, reference и SSR/Auth fingerprints PASS.

## Компактная форма профессии — 2026-10-23

Название и CLI-команда используют адаптивный product grid: две колонки при
достаточной ширине панели, одна при нехватке места. Селект иконки ограничен
220 px и сжимается на узком экране; цвет остаётся рядом. Описание использует
штатную высоту Textarea Base вместо собственного minimum 96 px.

Прежняя группа «Настройки выполнения» и подпись «Ключ запуска» заменены одним
понятным необязательным FormField «Профиль запуска агента» с связанным пояснением.
Это имя профиля у исполнителя, а не новая сущность Workflow. Wire-поле
launch_profile, nullable-значение, pattern и maxlength не менялись.

Вариант со сворачиванием исключён: проверка показала, что native validation
не фокусирует ошибочное поле внутри закрытого details. Итоговое поле остаётся
видимым и получает focus при ошибке; новый validation runtime не добавлялся.
Source extra_script полностью совпадает с входом этапа. Scoped итог: 6 PASS,
4 subtests, Ruff PASS. IAB: реальные 320/375/1024/1280/1920/2560 px, перенос
полей, компактный Select, отсутствие overflow, сохранность значений и native
validation. Начальный общий viewport override не менял целевую вкладку; такие
измерения исключены, итоговые получены адресно через IAB CDP и override снят.
Это локальный source-кандидат, не installed/production или hosted acceptance.

## Профиль убран из профессии — решение 2026-10-23

По уточнению владельца общий профиль не является настройкой профессии.
Поле удалено из формы, currentPayload и fillNamespaceForm; форма больше не
отправляет launch_profile, включая null. Прежняя запись API сохраняется для
совместимости установленных каталогов/admission и не стирается при сохранении
названия или оформления. Целевая привязка относится к конкретному workflow
в рамках профессии; перенос исполнения и данных пока не выполнен.
Этот пункт заменяет предыдущие рекомендации о поле профиля в форме профессии.

Это предметная композиция; компоненты и обработчики не изменены. В локальной
