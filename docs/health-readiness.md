# Быстрая проверка готовности

`/health` проверяет доступность БД, ревизию миграций и точную совместимость
схемы с ORM. Полный валидатор `session.schema_is_ready` остаётся каноническим:
он используется миграциями, QA и первой проверкой состояния схемы.

Повторный health переиспользует результат полной проверки только при неизменных
версиях системных каталогов и текущей ревизии Alembic. PostgreSQL: версии строк
метаданных принадлежащей приложению схемы (relations, columns, defaults,
constraints, indexes, triggers, functions, types, views, inheritance, sequences,
comments). SQLite: `PRAGMA schema_version`. Ревизия Alembic читается каждый раз.
При изменении выполняется полная проверка; при изменении во время сверки ответ
не становится успешным. TTL и фонового refresh нет. Ошибки БД не подменяются
сохранённым успехом; новый engine получает отдельное состояние.

Кеш принадлежит процессу и engine, не хранится в БД и не меняет пользовательские
данные. Обычные изменения данных не требуют повторной рефлексии всей схемы.
PostgreSQL maintenance может инвалидировать результат через catalog row version;
это безопасная лишняя сверка. После перезапуска первая проверка остаётся полной.

Проверки: public HTTP regression, немедленный отказ после DDL/revision drift,
восстановление после исправления, PostgreSQL budget не более 6 SQLAlchemy statements
на прогретый запрос. Сравнивать runtime latency/CPU на одном image и cap отдельно
в Compose и Kubernetes; unit tests не заменяют эти измерения.
