# Человеческие роли и приложения Workflow

Статус: feature-исходники, не установленная политика. Канон — Base
`docs/platform/HUMAN_APPLICATION_ACCESS.md`; экспорт SDK закрепляется Base pin.
Профессии и роли исполнителей не являются человеческими ролями.

## Вход и административные операции

SSO middleware получает текущую identity один раз от настроенного Auth,
проверяет proof через canonical Python SDK и помещает authority в request state.
JWT и PAT требуют приложение `project-workflow`; PAT сохраняет точный read/write
scope. Роль из proof актуальнее profile hint. Зарегистрированные технические
credentials не становятся людьми и не получают административные permissions.

`AUTH_APPLICATION_ACCESS_REQUIRED=true` включает обязательность действующего
`enforced` proof. Значение по умолчаниюfalse оставлено для этапа совместимого
rollout; оно не означает завершённую активацию. Настроенный Central Auth при
недоступности не переключается на standalone. Пустой app set возвращает403.
Страница отказа использует прежние theme tokens, показывает «Нет доступа» и
не предлагает повторный SSO для исправления отсутствующего разрешения.

Обычный пользователь читает процессы и выполняет разрешённые задания.
14 mutating routes профессий, workflow, фаз и инструкций объявляют общую FastAPI
admin dependency при регистрации. Страница создания профессии и редактор
инструкций также административные. CLI history/step, рабочие чтения и личная
CLI-справка не превращаются в общую конфигурацию.

Шаблоны используют ту же текущую authority через `can_administer`: обычный
пользователь видит процессы, фазы, инструкции и профессии без форм и действий
изменения. Просмотр, смена профессии/процесса/режима и Список/Схема сохраняются.
Редакторские scripts и autosave не публикуются в обычной странице. Это не
заменяет серверную dependency и не является проверкой открытой вкладки.

## Машинная совместимость

Namespace/Base reader introspection принимает новое поле `role=service_account`,
сохраняя exact registered subject и выдаваемые scopes. Human role, дажеadmin,
не открывает machine paths. Неизвестные claims не игнорируются. Существующий
строгий execution-context V2 не расширяется этой задачей.

## Открытые gates

Scoped SSO/machine/route и UI display-window checks подтверждают source-правила.
Migration0017 и native PostgreSQL fixture проверяют исходный request clock,
истечение в COMMIT и откат; deadline пространств и приложения пересекаются.
Успешные source checks не заменяют текущую authority владельца новых worker
стадий, filled migration/rollback и compatible cohort. Source flag не является
операторским guard активации. Полный gate, Docker/Kubernetes кандидаты,
dev/IAB под user/admin и реальное задание остаются отдельными обязательными
этапами до заявления о завершении.

## Совмещение с пространствами

Проверки включаются независимыми flags и используют один Auth readback.
Подтверждённый global user выполняет рабочие операции только при наличии
writable project admission. Запрет пространства, архив или чужой проект не
обходятся выдачей приложения. Конфигурация по-прежнему требует global admin.
Legacy member остаётся read-only до явной миграции, прежние технические контракты
не превращаются в третью человеческую роль.

Неизменяемый project scope получает минимум исходных deadline. Display window
действует и при выключенной политике пространств: application authority имеет
собственный исходный срок. При совместном включении используется меньший срок;
повторная загрузка страницы и промежуточный кеш не продлевают подтверждение.
Изменение identity, роли, списка приложений или ревизии меняет display revision,
а обновление только исходного срока не уничтожает неизменённый черновик.

Меню фильтрует копию публичного каталога по текущему пользователю. Общий кеш
каталога не хранит личные разрешения. Админ видит все подключённые приложения,
включая новые, даже если его сохранённый список пуст. Истёкшая authority и
отсутствующий proof при настроенном Central Auth закрывают меню и страницу.
Explicit standalone остаётся отдельным режимом, без скрытого fallback.

Отдельный request clock ограничивает ORM-чтение, flush и commit независимо от
space policy. Он содержит только исходный срок и сам не выдаёт полномочий.
Аддитивная PostgreSQL-миграция устанавливает row/deferred COMMIT guards на
защищённых таблицах. Временная настройка принадлежит транзакции; следующий
native запрос на том же соединении её очищает и сохраняет свои собственные
проверки. SQLite остаётся тестовым режимом с ORM-проверками.

Native PostgreSQL-проверка использует реальный SAUnitOfWork, новую миграцию и
задержку внутри COMMIT: истёкшая запись откатывается; свежая и отдельно
авторизованная native запись работают. Это не является проверкой внешних
эффектов, новой стадии worker или всего runtime.
Проверены обе независимые конфигурации, отзыв приложения и пространства в той же
сессии и более короткий application proof. Это не завершает actor-проверку
автономных machine stages или полную dev приёмку.
