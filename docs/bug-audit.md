# Реестр post-merge аудита багов

Реестр фиксирует только дефекты существующего `project-workflow`. Новые
продуктовые возможности, слои совместимости и дополнительные runtime-компоненты
в этот аудит не входят.

## Подтверждённые дефекты

| ID | Аспект | Дефект | Доказательство | Статус |
| --- | --- | --- | --- | --- |
| BUG-001 | SQLite test helper | Обработчик подключения проверял отсутствующий `connection_record.dialect`, поэтому `foreign_keys=0` и `journal_mode=delete`; SQLite-тесты не воспроизводили FK-поведение PostgreSQL. | Регрессия проверяет `PRAGMA foreign_keys=1` и `journal_mode=wal`. | Исправлено |
| BUG-002 | Web UI / REST | Reorder фаз сериализовал `data-*` как JSON-строку, хотя strict API требует integer; действие из браузера получало `422`. | Template regression проверяет явное числовое преобразование `phase_id`. | Исправлено |
| BUG-003 | UI / fail-closed | Задача со статусом `blocked` исчезала из списка незавершённых на дашборде, а общий DTO подписывал её как «В работе». | Service regression проверяет видимость blocked-задачи и метку «Заблокирована». | Исправлено |
| BUG-004 | Локализация | Ошибка удаления единственной фазы и blocker сбоя evaluator возвращались на английском. | API и Supervisor regression tests проверяют русские сообщения. | Исправлено |
| BUG-005 | UI / cleanup | Карточка задачи всегда показывала «Время в работе —»: у поля не было producer, storage или вычисления. | Caller sweep нашёл только template context и test fixture; template regression запрещает мёртвую метрику. | Исправлено |
| BUG-006 | Audit / целостность | Runtime позволял удалить задачу вместе с audit-историей через cascade, поэтому журнал не был неизменяемым. | DELETE route, UI-действие и mutation methods удалены; FK audit-таблиц используют `RESTRICT`, PostgreSQL regression запрещает удаление задачи с историей. | Исправлено |
| BUG-007 | Supervisor / agent concurrency | Имя или Hermes-профиль назначенного агента могли измениться после финальной перепроверки контракта, но до commit verdict. | PostgreSQL barrier-test проверяет порядок `agent → workflow` и ожидание commit Supervisor. | Исправлено |
| BUG-008 | Supervisor / производительность | Загрузка каталога выполняла отдельные запросы инструкций, checks, evidence и агента для каждой фазы. | Каталог собирается четырьмя batch-запросами после чтения фаз; query-count regression не зависит от числа фаз. | Исправлено |
| BUG-009 | Web UI / phase aggregate | Очистка текста существующей check/evidence удаляла строку только из DOM и не сохраняла изменение. | Template regression требует save при empty blur и восстановление удалённого DOM-узла при отказе aggregate update. | Исправлено |
| BUG-010 | Domain / CLI contract | `TaskService` проверял только префикс и принимал `RUN`, `RUN-RACE` и `RUN-12X`, хотя поддерживаемый CLI требует `PREFIX-<число>`. | Unit regression проверяет общий `TaskKeyValidator`; примеры CLI приведены к `RUN-42`. | Исправлено |
| BUG-011 | REST / strict contract | Создание записи могло неявно выбрать default workflow через runtime-bootstrap. | `POST /api/namespaces` требует strict positive integer `workflow_id`; каталог создаётся только `init_db.py`, отсутствующий workflow возвращает `404`. | Исправлено |
| BUG-012 | Локализация / diagnostics | Ошибка отсутствующего `DATABASE_URL` и diagnostics повреждённых persisted JSON-полей были на английском и могли попасть в CLI/log diagnostics. | Localization regressions проверяют русские configuration и corruption errors; parser LLM остаётся техническим и скрыт fail-closed от пользователя. | Исправлено |
| BUG-013 | Strict validation | `InstructionService` превращал строковый `step_num` и `bool` в целое, а reorder принимал `bool` как instruction ID, хотя REST DTO запрещали эти формы. | Service/API regressions проверяют string/float/bool/non-positive IDs и отсутствие записей при отказе. | Исправлено |
| BUG-014 | Recorder / security | Raw URL/query strings с `access_token`, `refresh_token`, `client_secret`, `private_token` и похожими параметрами не маскировались; exact nested keys тоже были неполными. | Recorder regressions проверяют query/assignment и nested-key redaction, а также safe near-miss (`token_count`, `client_secret_name`). | Исправлено |
| BUG-015 | Web UI / feedback | После успешной перестановки инструкций toast создавался без типа и получал несуществующий класс `toast-undefined`. | Template regression требует явный тип `success` и запрещает однопараметрический вызов. | Исправлено |
| BUG-016 | CLI / локализация | Справка CLI и вывод версии оставляли стандартные заголовки и сообщения Click на английском (`Usage`, `Options`, `Commands`, `Show...`, `version`), а описания команд начинались с `Step`/`History`. | CLI regressions проверяют корневую и вложенную справку, сообщение версии и запрещают английские служебные строки. | Исправлено |
| BUG-017 | Web UI / локализация | Дашборд, список и карточка задачи показывали сырые verdict-коды (`PASS`, `BLOCKED`) вместо русских пользовательских меток. | Service/template regressions проверяют единое отображение verdict; браузерная проверка подтвердила русские метки в реальном UI. | Исправлено |
| BUG-018 | Supervisor / replay | Накопленное покрытие влияло на prompt и итог parser, но не входило в fingerprint; старый частичный результат мог replay-иться после другого отчёта и вернуть устаревшие `covered`/`missing`. | Unit и PostgreSQL concurrency regressions различают последовательный устаревший кеш и run, созданный конкурентно из того же snapshot. | Исправлено |
| BUG-019 | Supervisor / coverage | Поиск накопленного покрытия молча ограничивался 200 последними run и выполнял отдельный поиск фазы для каждого из них; раннее покрытие исчезало из последующих оценок. | Regression с 201 run проверяет полный phase-scoped результат без произвольного лимита и N+1 lookup. | Исправлено |
| BUG-020 | PostgreSQL / ordering | Checks, evidence, task history, agents и эти записи читались без `ORDER BY`; после физической реорганизации таблиц менялись evaluator fingerprint/prompt, история и выбранные UI-элементы. | PostgreSQL regression кластеризует таблицы по убывающему ID и требует стабильный канонический порядок repository reads. | Исправлено |
| BUG-021 | Web UI / phase aggregate | Debounced и прямые полные `PUT` сохранения фазы могли выполняться одновременно, поэтому более старый snapshot мог завершиться последним и затереть новое состояние. | Все aggregate saves проходят через одну Promise-очередь; template regression и in-app Browser проверяют сохранение и восстановление данных после reload. | Исправлено |
| BUG-022 | PostgreSQL / ресурсы | Cached engine сравнивался с текстовым DSN, в котором SQLAlchemy скрывал пароль, поэтому каждый вызов `get_engine()` создавал новый pool. При смене DSN, reset и неудачной проверке подключения старые engine не освобождались. | Session regressions проверяют повторное использование password DSN и обязательный `dispose()` при retry, смене DSN и reset. | Исправлено |
| BUG-023 | Runtime cleanup | В production оставались test-only `_skip_default_phase`, отдельные phase mutation wrappers, optional-int parser и зарегистрированные заглушки удалённых API. Они создавали обход канонического bootstrap/aggregate contract и загрязняли route table. | Caller-sweep не находит production consumers; тестовые каталоги создаются test-local helper, а удалённые пути разрешаются обычным router `404/405`. | Исправлено |
| BUG-024 | REST / локализация | DTO validation возвращала стандартные английские сообщения FastAPI/Pydantic, а неподдерживаемый HTTP-метод — английский `Method Not Allowed`. | API regressions проверяют безопасный русский `422` с именами полей и русский `405` без внутренних данных. | Исправлено |
| BUG-025 | Supervisor / конфигурация | При стандартном OpenRouter и пустом `OPENAI_API_KEY` runtime выполнял заведомо бесполезный внешний запрос, а пользователь видел технический класс исключения (`HTTPError`, `ValueError`) вместо безопасной русской причины. Отдельный `is_available()` не имел runtime-consumers. | Регрессии запрещают сетевой вызов OpenRouter без ключа, сохраняют безключевые custom endpoints и проверяют локализованные категории ошибок без текста исключения. | Исправлено |
| BUG-026 | Runtime / безопасность | PostgreSQL retry и FastAPI lifespan логировали полный текст DB-исключения, `app.state.startup_error` без consumers сохранял его, а `init_db.py` мог вывести traceback. Исключение способно содержать DSN, SQL и сетевые детали. | Типизированный `DatabaseUnavailable` возвращает безопасное русское сообщение и exit `1`; regressions подставляют secret-маркеры и запрещают их в логах, state и stderr. | Исправлено |
| BUG-027 | Supervisor / переходы | Transition recorder молча игнорировал отсутствующую задачу, подставлял ей статус `active`, завершал workflow при неизвестной следующей фазе и откатывал без target на текущую фазу. Reload сохранял stale task после её удаления. | Recorders требуют полное актуальное состояние задачи и существующие phase targets; нарушения дают контролируемый concurrent conflict без записей, а reload очищает удалённую задачу. | Исправлено |
| BUG-028 | Runtime / конфигурация | `_AppState` повторно разбирал `DATABASE_URL` до канонического DB factory, поэтому некорректный DSN в UI/API/CLI path обходил безопасный `DatabaseUnavailable` и выбрасывал сырой `sqlalchemy.ArgumentError`. | Парсинг и нормализация SQLite path принадлежат `get_engine()`; regression проверяет безопасную ошибку без secret-marker и абсолютный canonical SQLite path. | Исправлено |
| BUG-029 | Readiness | Request middleware создавал UoW раньше `/health`, поэтому при недоступной БД readiness handler не выполнялся и сервер отвечал общим `500` вместо безопасного `503`. Существующий тест подменял только внутренний вызов handler и не моделировал отказ middleware. | Middleware не создаёт request UoW для `/health`; regression одновременно запрещает создание UoW и проверяет безопасный `503 database-unavailable`. | Исправлено |
| BUG-030 | PostgreSQL / ownership | Простые FK не гарантировали, что project, task, phase event и step-history относятся к одному workflow и одной задаче. | Составные FK закрепляют project/workflow задачи, task/workflow фаз и точную пару event/task для step-history; прямые SQL-regressions проверяют каждый отказ. | Исправлено |
| BUG-031 | Supervisor / parallel routing | При чередовании связанных и изолированных parallel-фаз переход вычислялся по физически последней фазе группы и мог пропустить следующую каноническую execution-группу. | Регрессии проверяют переходы для связанной группы и изолированной parallel-фазы через единое доменное разбиение. | Исправлено |
| BUG-032 | CLI / strict input | Явный `--report ""` или отчёт из пробелов интерпретировался как отсутствие параметра и показывал инструкции вместо контролируемого отказа. | CLI regressions требуют `BLOCKED`, exit code `1` и отсутствие создания DB engine для пустого отчёта. | Исправлено |
| BUG-033 | Domain / diagnostics | Regex для ключа, состоящего только из цифр, содержал лишнее экранирование и не выдавал предназначенную диагностическую причину. | Regression проверяет точное русское сообщение для ключа `123`. | Исправлено |
| BUG-034 | Supervisor / replay | Версия evaluator prompt не входила в contract fingerprint, поэтому успешный run мог replay-иться после изменения правил проверки без повторного вызова provider. | Unit и end-to-end regressions меняют `PROMPT_VERSION` и требуют новый fingerprint и повторную оценку. | Исправлено |
| BUG-035 | Runtime / безопасность | Локальный UI по умолчанию слушал `0.0.0.0`, хотя приложение не содержит встроенной аутентификации. | Конфигурационный regression требует `127.0.0.1`; Compose сохраняет `0.0.0.0` только внутри контейнера и публикует порт на loopback. | Исправлено |
| BUG-036 | Supervisor / prompt | Assignment prompt содержал пример `RUN-42` вместо ключа текущей задачи и мог направить исполнителя к чужому идентификатору. | Context и prompt regressions проверяют текущий `task_key` и отсутствие захардкоженного примера. | Исправлено |

| BUG-038 | Cleanup / документация | В репозитории оставались Alembic revision template, тесты давно удалённых routes и setup-фаз, а README/live plan описывали отсутствующий systemd service и прежние Jira/GitLab contracts. | Caller scan подтверждает отсутствие template consumers; документация описывает фактический Compose и Relevanter Business/Tech, stale route tests удалены. | Исправлено |

## Следующие проверки

  неверной revision и ошибке seed до первой записи; SQLite-набор и PostgreSQL
