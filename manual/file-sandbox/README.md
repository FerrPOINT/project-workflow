# Ручная приёмка агента через CLI Workflow

Проверять путь **штатный CLI → настоящий Workflow API → настоящий advisor →
сохранённая фаза и история**. Агент читает очередной шаг, выполняет его и отправляет
отчёт. Не заменять этот путь вызовом Python-классов или непосредственной записью в БД.

## Подготовка оператором

1. Сверить актуальные source SHA, установленный Workflow API и исполняемый CLI.
   Сохранить их происхождение. Не считать имя image доказательством версии.
2. Использовать настоящие Auth и Tracker в PDLC1. Создать отдельные тестовые
   задания и действующие назначения; зарегистрировать тестовые воркфлоу в коллекциях
   соответствующих профессий. Рабочие бизнес-воркфлоу и историю не заменять.
3. Заранее настроить обычные `PROJECT_WORKFLOW_URL`, `PROJECT_WORKFLOW_API_TOKEN`,
   `FLEET_AGENT_ID`, `PROJECT_WORKFLOW_NAMESPACE_ID`; токен не передавать в аргументах.
   Для каждого режима использовать его действительное назначение и профессию.
4. Создать отдельный каталог файлов; эта команда не создаёт задачи и не выставляет фазы:

```sh
python manual/file-sandbox/cli.py prepare --root .local/cli-acceptance-001
```

Режимы: PM/draft, Analyst/analysis, Architect/decomposition, Developer/initial,
Developer/rework, Reviewer/delivery, Tester/delivery, DevOps/delivery. Во всех
тестовых воркфлоу три фазы файловой работы: инвентаризация, изменения, проверка.
Инструкции и критерии фиксируются до первого шага. Исходные файлы: `notes.md`,
`settings.json`, `items.csv`, `calculator.py`, `obsolete.txt`. Агент создаёт
инвентаризацию и тесты, изменяет содержимое, исправляет расчёт и удаляет старый файл.
`prepare` сохраняет их в `workflows.json` и фиксирует hash в manifest. Recorder
отклоняет изменение этого файла после подготовки. Однократную регистрацию выполняет
оператор через существующий импорт каталога, передавая `workflows.json` и hash из
manifest в `register_catalog.py --installation pdlc1 --catalog <file> --expected-sha256 <hash>`.
Команда запускается в проверенном локальном контейнере PDLC1 с
`SDLC_MAINTENANCE_PROJECT=pdlc1` и настроенной БД Workflow. Она создаёт только
тестовые определения в коллекциях уже установленных профессий. Повтор читает
идентичный каталог; изменённые или частично сохранившиеся определения отклоняются
без перезаписи. Она не создаёт задачи, назначения, фазы выполнения,
оценки или историю. Задачи и назначения оператор готовит отдельно через Tracker;
все действия агента после этого выполняются только штатным CLI.

## Действия агента

```sh
project-workflow --json step --task CLI-101
# Прочитать возвращённые инструкции и выполнить их в своём каталоге.
# Подать фактический отчёт на stdin этой команды:
project-workflow --json step --task CLI-101 --report - --operation-key CLI-101-first-1 --expected-version 1
project-workflow --json history --task CLI-101
```

Ключ задачи здесь пример; версию брать из фактического ответа CLI. Для финального
PM-отчёта передать подтверждённые владельцем редакцию и hash требований, когда CLI
запрашивает эти параметры. При PARTIAL выполнять замечания и отправлять новый отчёт
с новой операцией и актуальной версией. При неизвестном результате HTTP сначала
читать `history --operation-key` исходной операции; не менять её тело или ключ.
Замечание advisor, противоречащее фактам, сохранять как дефект проверки.

В каждом режиме перед выполнением второй фазы честно отправить отчёт, что
изменения ещё не выполнены. Для recorder отметить эту команду флагом
`--incomplete-probe`. Он передаёт текст агента без изменений. Advisor должен
отклонить отчёт и сохранить фазу; если он принимает его, проверка получает FAIL.
После этого выполнить задание и продолжить по фактическим ответам CLI.

Для сохранения команд и ответов допускается recorder, который запускает тот же
установленный CLI отдельным процессом. Он не выполняет задания и не выбирает
следующую фазу. Например, получение шага и отправка подготовленного отчёта:

```sh
python manual/file-sandbox/cli.py step --root .local/cli-acceptance-001 --case analyst-analysis --task CLI-101
python manual/file-sandbox/cli.py step --root .local/cli-acceptance-001 --case analyst-analysis --task CLI-101 --report .local/report.txt --operation-key CLI-101-first-1 --expected-version 1
python manual/file-sandbox/cli.py history --root .local/cli-acceptance-001 --case analyst-analysis --task CLI-101
```

Recorder сохраняет точные argv, отчёт stdin, stdout/stderr и снимки файлов.
Отчёты пишет агент по выполненным действиям; готовые «успешные» ответы не генерируются.
Не импортировать recorder из application runtime и не добавлять его в обычную suite.

## Приёмка и доказательства

Для каждого из восьми режимов нужны реальные вызовы `step`, отправка отчётов,
три принятые фазы и завершённая задача в полном выводе `history`. Отправленные
отчёты и операции должны совпасть с историей. Дополнительно проверить файлы,
создание/изменение/удаление, результаты тестов и независимые арифметические примеры.
Recorder проверяет эти условия командой `finish` после завершения всех режимов:

```sh
python manual/file-sandbox/cli.py finish --root .local/cli-acceptance-001
```

Пустой, частичный или неуспешный прогон не получает PASS. Отдельно указывать
проверенные режимы, замечания advisor, source/runtime/CLI версии и ограничения.
Открыть историю фактических задач в Workflow через Codex IAB. Не выдавать зелёные
unit-тесты, прямую диагностику ядра или проставленный оператором статус за эту приёмку.

## Проверка recorder

`python manual/file-sandbox/cli_checks.py` проверяет передачу stdin, сохранение
ответов, неизвестный результат при timeout и отказ от незапущенного прогона.
Это unit-проверка recorder, без настоящего агента и модели.
`python manual/file-sandbox/catalog_checks.py` отдельно проверяет регистрацию
каталога, сохранность профессий, отсутствие задач и проверку идентичного повтора.

## Историческая диагностика

`run.py` и `checks.py` сохранены для чтения и воспроизведения старых результатов
ядра. Единственный явно названный запуск движка — `engine-diagnostic`; его PASS
не является приёмкой CLI. История и критерии прежнего прогона не переписываются.
Текущую приёмку выполняют только по порядку выше.
